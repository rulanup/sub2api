# 用户使用记录缓存命中率展示设计

日期：2026-08-31

## 目标

在用户端“使用记录”的 Token 列中，除输入和输出 Token 外，直接显示缓存读取 Token 与缓存命中率。视觉上沿用现有两行 Token 布局，并匹配已确认的参考截图。

## 范围

- 修改 `UsageTable` 的 Token 单元格展示；用户端使用记录复用该组件，因此无需新增页面组件。
- 不增加后端字段或接口；使用现有 `input_tokens`、`cache_read_tokens`、`cache_creation_tokens`。
- 不改变 Token 详情浮层、CSV 导出、管理员筛选和统计接口。
- 图片、视频和按次计费记录继续使用现有非 Token 展示。

## 展示与计算

Token 请求的第二行保留缓存读取/创建数量，并在缓存信息后显示“缓存命中率”。命中率定义为：

```text
cache_read_tokens / (input_tokens + cache_read_tokens + cache_creation_tokens) * 100
```

该口径与现有 TokenUsageTrend 的命中率计算一致，将缓存创建也纳入提示词总量。百分比显示 1 位小数；分母为 0 时返回 0%。因此有输入但未命中缓存时显示 0%，仅缓存创建时也显示 0%。

当记录没有任何提示词 Token 时，不额外显示缓存率；图片/视频/按次计费请求不显示缓存率。

## 数据流与错误处理

数据由现有 usage API 返回，前端在表格渲染时计算，不引入异步请求。计算函数对 `null`、`undefined`、负值和非有限数字进行安全归零，避免产生 `NaN%` 或 `Infinity%`。显示格式通过现有 i18n key `usage.cacheHitRate`，同时覆盖中英文。

## 测试

为 `UsageTable` 增加回归测试，验证：

1. 示例数据计算并显示 99.5% 等一位小数结果。
2. 无缓存读取但有输入时显示 0%。
3. 仅缓存创建时分母包含创建 Token，显示 0%。
4. 分母为 0 时不显示无效数值。
5. 图片/按次计费仍显示图片内容且不出现缓存率。

现有表格、用户使用记录和前端类型检查必须保持通过。
