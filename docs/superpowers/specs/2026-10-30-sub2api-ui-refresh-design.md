# sub2api 全站 UI 刷新设计规格

## 1. 背景与目标

sub2api 当前前端已经具备完整业务能力，但视觉语言混用了大面积渐变、玻璃拟态、发光阴影、偏大的圆角和多种灰阶，导致页面更像营销模板，而不是高频使用的 B 端产品。

本次改版采用已确认的方案 A「冷白大厂极简」：在不改变后端业务、路由能力、权限逻辑、国际化、运行时主题和现有组件体系的前提下，建立一套克制、统一、易扫读的前端视觉系统。

成功标准：

- 管理端、用户端和认证页呈现同一套产品语言。
- 页面首先服务于信息层级和操作效率，不依赖装饰吸引注意力。
- 列表、表单、弹窗、抽屉、反馈状态在浅色和深色模式下均保持一致。
- 表格在自身容器内完成横向滚动，移动端不产生页面级横向溢出。
- 现有主题切换、国际化、响应式布局和业务流程不退化。

## 2. 范围

### 覆盖范围

- Tailwind 主题配置和全局 CSS 设计令牌。
- 应用壳层：侧栏、顶栏、页面容器。
- 通用组件：按钮、输入框、选择器、卡片、统计卡、表格、徽章、页签、开关、下拉、弹窗、抽屉、空状态和加载状态。
- 代表性页面：管理员 Dashboard、用户管理、渠道管理、系统设置；用户 Dashboard、API Key、用量和资料页；登录、注册、找回密码等认证页。
- 对全站残留的 `glass`、发光、渐变、网格和模糊装饰样式做统一收敛。

### 非目标

- 不修改后端 API、数据库、计费、权限和业务流程。
- 不引入 Ant Design、Element Plus 等第二套组件库。
- 不重写路由、状态管理或 i18n 数据模型。
- 不移除用户可配置的品牌主色能力。
- 不新增营销页面、装饰插画或与业务无关的动画。

## 3. 视觉方向

### 色彩

- 浅色模式画布使用冷白到浅灰的中性层级，内容面保持纯白。
- 主文字使用接近黑色的冷墨色；次文字使用中性灰；弱提示不得低于可读性要求。
- 默认品牌色调整为稳重的产品蓝，继续由现有 CSS 变量和运行时主题系统驱动。
- 品牌色只用于主操作、选中态、链接、焦点环和关键数据强调。
- 状态色保持语义：成功为绿、警告为琥珀、危险为红、信息为蓝；禁止无业务含义的彩虹色。
- 深色模式采用中性灰黑层级，不出现彩色发光或高饱和大面积底色。

### 几何

- 常规卡片、输入框和按钮使用 8 至 10px 圆角；小型控件使用 6 至 8px。
- 外框与内部元素遵守同心圆角关系，内层圆角不超过外层圆角减内边距后的合理值。
- 边框以半透明中性色微边框为主，避免粗黑分割线和 1px 实色重边。
- 阴影仅用于真正脱离文档流的浮层；静态卡片使用边框和底色区分，不依赖投影。
- 图标与文字组合按光学重心校正，避免机械居中造成视觉偏移。

### 排版与密度

- 页面标题、区块标题、正文、辅助文字建立明确四级层级。
- 正文以 14px 为主，辅助信息以 12px 为主，标题不做无意义的超大字号。
- 顶栏和侧栏保持稳定尺寸，页面内容通过留白而非大卡片制造层级。
- Dashboard 的核心 KPI 控制在 4 至 6 个重点指标；次要指标进入更轻量的摘要区域。
- 表单标签置顶；说明文字只在能减少歧义时出现，避免重复标签含义。

### 动效

- 只保留 120 至 180ms 的颜色、透明度和轻微位移动效。
- 不使用循环呼吸、发光、漂浮、网格移动等装饰动画。
- 尊重 `prefers-reduced-motion`，关闭非必要过渡。

## 4. 信息架构与页面骨架

### 应用壳层

- 侧栏使用实色中性面，与内容区以微边框分隔。
- 品牌区域降低视觉权重，只保留标识、产品名和折叠控制。
- 导航项保持紧凑行高；当前项使用浅品牌底、深品牌字和左侧 2px 指示线，不使用整块高饱和色。
- 顶栏使用实色白或深灰，高度保持 56 至 64px，底部使用微边框。
- 顶栏左侧显示页面标题，右侧集中放置公告、语言、余额、帮助和用户菜单。
- 移动端继续使用抽屉式侧栏；顶栏操作按优先级折叠，不产生拥挤或遮挡。

### 列表页

统一采用以下顺序：

1. 页面标题与唯一主操作。
2. 可选摘要或关键状态。
3. 筛选和搜索工具栏。
4. 数据表格。
5. 分页与批量操作。

规则：

- 一个独立操作区最多一个 Primary 按钮。
- 筛选控件按常用度排列，低频条件放入可展开区域。
- 表格外层负责圆角和边框，内部滚动容器负责横向滚动和粘性表头。
- 固定列使用底色和细阴影区分，不出现生硬截断。
- 行高、单元格内边距和操作列宽度保持统一。
- 加载、空数据、错误、无权限和无搜索结果分别呈现，不复用含糊的空白页。

### 表单与设置页

- 页面标题下直接进入分组表单，避免多层嵌套卡片。
- 标签置顶，必填和校验提示紧邻字段。
- 设置页页签不得截断中文标签；窄屏可横向滚动或转为下拉选择。
- 即时保存与显式保存必须在视觉和文案上明确区分。
- 开关用于立即生效的二元设置，不用于需要提交确认的复杂选择。

### 详情与编辑

- 查看详情优先使用侧边抽屉或同页展开，保留列表上下文。
- 需要独立协同、分享或长流程编辑时使用独立页面。
- 简单确认使用紧凑弹窗；含表单的弹窗必须防止误点遮罩丢失内容。
- 删除、扣费、清空等高危操作必须使用确认对话框，标题说明对象，描述说明不可逆后果，按钮使用明确动宾文案。

### 认证页

- 使用中性画布和居中的白色内容卡片。
- 保留品牌标识、表单标题和必要的帮助链接。
- 移除光球、网格、渐变文字和玻璃卡片。
- 桌面端控制卡片宽度在 380 至 440px；移动端铺满安全边距内的可用宽度。

## 5. 组件规范

### 按钮

- Primary：品牌色实底，用于当前区域唯一主操作。
- Secondary：白色或中性面、微边框，用于普通操作。
- Ghost：无底色，用于工具栏和低权重操作。
- Danger：只在不可逆操作最终确认时使用红色实底。
- 审批通过和驳回属于责任对等操作，默认均使用次级按钮。
- 图标按钮必须有 `aria-label` 和清晰焦点态。

### 输入与选择

- 输入框、选择器、日期控件高度一致。
- 默认态使用中性微边框；悬停态略加深；焦点态使用品牌色边框和柔和焦点环。
- 错误态同时提供红色边框、图标或错误文案，不只依赖颜色。
- Select 只用于互斥且选项较少的输入；大量选项使用可搜索选择器。
- Radio 用于少量互斥选项；Switch 用于立即生效的二元设置。

### 卡片与统计卡

- 静态卡片使用纯白/深灰面、微边框，默认无阴影。
- 卡片头部与内容区以微边框分隔，内边距统一。
- 统计卡显示标签、主数值、可选趋势和短说明。
- 图标使用中性浅底和品牌色或语义色，不使用随机彩虹背景。
- 可点击卡片只在悬停时轻微改变边框和底色，不做明显上浮。

### 表格

- 表头使用浅中性底、深色文字和细分隔线。
- 数字右对齐，文本左对齐，状态居中对齐。
- 操作列固定在右侧；重要标识可固定在左侧。
- 固定列表头与单元格背景必须一致，滚动时边界清晰。
- 分页在桌面端右对齐，移动端可换行。
- 表格自身设置 `overflow-x: auto`；页面根节点不得出现横向滚动条。

### 徽章与状态

- 默认使用浅底深字，避免高饱和实底。
- 色彩与文案共同表达状态，不允许只用颜色。
- 同一状态在全站使用相同色彩语义和命名。

### 页签

- 使用底部指示线或轻量胶囊选中态，不使用大面积渐变。
- 标签保持单行；空间不足时横向滚动，不截断中文。

### 浮层

- 下拉菜单、Popover 和 Tooltip 使用纯色面、微边框和轻量阴影。
- 弹窗桌面端宽度按内容分为紧凑、标准和宽版，垂直位置略高于视口中心。
- 移动端弹窗转为接近全宽并限制最大高度。
- 抽屉桌面端从右侧进入，移动端接近全屏。
- 所有浮层具备 Esc 关闭、焦点管理和点击外部关闭策略；含表单的弹窗禁用遮罩关闭。

## 6. 状态与反馈

- 加载状态使用尺寸稳定的骨架或轻量 Spinner，避免布局跳动。
- 空状态包含明确标题、一句解释和最多一个主操作。
- 错误状态说明发生了什么、用户可做什么，并提供重试入口。
- Toast 用于短反馈，不承载必须阅读或确认的信息。
- 危险操作成功后必须提供可感知反馈；失败时保留用户输入并说明原因。
- 所有交互元素具备可见焦点态；颜色对比满足 WCAG AA 的正文可读要求。

## 7. 响应式与可访问性

- 桌面端侧栏宽度保持稳定，折叠后只保留图标和可访问名称。
- 平板端优先压缩页面内边距，不提前隐藏关键操作。
- 移动端使用单列布局，筛选器可折叠，表格允许容器内横向滚动。
- 触控目标最小 40px，主要按钮和导航项建议 44px。
- 键盘可完成导航、表单、页签、弹窗和抽屉的主要操作。
- 页面切换和错误反馈对屏幕阅读器可感知。
- 深色模式不得只做颜色反转；边框、浮层和状态色需单独校准。

## 8. 技术边界

- 继续使用 Vue 3、Vite、Tailwind 和现有自研组件。
- 保留 `primary-*` Tailwind 色彩别名和运行时 CSS 变量接口。
- 为避免页面回归，保留现有工具类名称；通过调整其实现收敛视觉，而不是要求 96 个页面同时改类名。
- 全局样式负责稳定的视觉契约；页面级样式只表达页面特有布局。
- 不增加前端运行时依赖。
- 不在本地安装依赖；所有构建和浏览器验证在远程 Linux 项目完成。

## 9. 实施顺序

1. 建立令牌与全局基础样式。
2. 改造应用壳层与认证布局。
3. 改造通用表格、卡片、按钮、输入、浮层和状态组件。
4. 改造代表性管理员页、用户页和认证页。
5. 清理全站残余装饰样式。
6. 在远程执行生产构建。
7. 登录检查桌面、移动端、深色模式和关键交互。

## 10. 验收标准

### 视觉

- 页面中不存在大面积 mesh 渐变、模糊光球、玻璃卡片和彩色发光。
- 品牌色在单一页面中只承担操作和状态强调，不铺满装饰区域。
- 卡片、输入框、按钮、表格和浮层的圆角、边框和间距一致。
- Dashboard 信息层级清楚，核心指标不被大量同权卡片淹没。

### 布局

- 1440px、1024px、768px 和 390px 视口下均无页面级横向溢出。
- 用户管理表格在窄屏下由表格容器横向滚动，固定列和表头正常。
- 系统设置页签中文不截断。
- 移动端侧栏、顶栏和主要操作可正常使用。

### 功能

- 管理员和普通用户登录后均可进入对应首页。
- 主题切换、深色模式、语言切换、导航、筛选、分页、弹窗、抽屉和表单校验不退化。
- 远程 `pnpm build` 成功。

### 检查页面

- 认证：登录、注册、找回密码。
- 管理端：Dashboard、用户管理、渠道管理、系统设置。
- 用户端：Dashboard、API Key、用量、资料。
- 浮层：至少一个弹窗、一个抽屉、一个下拉菜单和一个危险操作确认框。

## 11. 交付方式

- 在 `codex/ui-refresh` 分支提交改动。
- 不直接覆盖远程 `main`，未经授权不 push。
- 完成后提供构建结果、登录验证、页面检查结果和 Git diff 摘要。
