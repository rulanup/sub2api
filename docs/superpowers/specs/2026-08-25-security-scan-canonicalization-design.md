# 安全扫描多层编码归一化设计

## 目标

修复通过 HTML 实体、URL 百分号编码、字面量 Unicode 转义、零宽字符、全角字符和分隔符混淆绕过输入审核的问题，同时保留“审计节点超时/不可用时放行正常请求”的现有策略。

## 设计

新增共享的安全扫描文本归一化组件。它只处理审核副本，不修改客户端原始请求，也不改变发往主上游的内容。归一化采用有界固定点循环：每轮依次解码 HTML 实体、合法 URL 百分号片段、字面量 Unicode 转义和可读的长 Base64 片段；然后执行 Unicode NFKC 归一化、移除零宽/格式字符、折叠全角字符和空白。审核文本保留原始大小写，紧凑匹配文本和规则匹配使用大小写折叠。

最多执行 4 轮并限制输入和中间结果长度，覆盖 Base64 → HTML 实体 → 百分号 → `\\uXXXX` → 中文以及交错/重复编码；达到上限后停止。Base64 仅尝试解码达到最小长度、结果为合法 UTF-8 且主要由可打印字符组成的片段，降低把 API Key 等不透明值误当作文本的风险。百分号解码逐个处理合法 `%HH` 片段，无效编码保持原样，不因为单个非法片段导致整段跳过。

本地网络安全策略使用归一化文本和紧凑文本匹配高置信度组合，优先于风险评分和外部 AI 审计。命中时直接返回 `network_security_policy_violation`，记录风险事件；防御性/授权语境继续进入 AI 审计。外部审计节点异常仍按现有 fail-open 逻辑处理。

内容审核服务也将使用同一归一化文本作为发送给审计模型的副本，避免本地策略与 Qwen3Guard 看到不同的编码形态；主请求体保持不变。

## 测试与验收

- 真实中文高风险输入被本地策略拦截。
- 同一高风险短语经过 HTML 实体、URL 编码、字面量 `\\uXXXX`、零宽字符、全角字符和混合多层编码后仍被拦截。
- 防御、学习、授权测试语境不会被本地策略直接拦截，而是交给 AI 审计。
- 归一化只影响审计副本，网关发送给主上游的原始 body 字节不变。
- 外部审计节点超时、不可用和 malformed response 的 fail-open 行为保持不变。
